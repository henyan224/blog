## 第一章：你到底在卖什么？

很多人以为机场卖的是"翻墙"。不对。拆开来看，你卖的是三样东西：

**1. 出口带宽**

你的 VPS 到目标网站（Google / YouTube / ChatGPT）的网络通道。

简单说：用户的手机/电脑没法直接访问 Google，但你的美国 VPS 可以。用户把请求发给你的 VPS，VPS 代替用户去访问 Google，再把结果传回来。这条「用户 → 你的 VPS → Google」的通道就是出口带宽。

它的"宽度"决定了同时能跑多少流量 —— 就像水管，管子越粗，同时能过的水越多。VPS 商家卖给你的通常是「1Gbps 带宽 + 每月 1-2TB 流量」，意思是管子最粗 1Gbps，但每月总共只能流过 1-2TB 的水。

**2. IP 身份**

不同国家/地区的 IP 地址，决定了用户"在哪个国家上网"。

**3. 连接质量**

延迟、速度、稳定性，决定了用户体验。

---

这三样东西的成本结构完全不同：

| 你卖的 | 成本来源 | 可复用性 |
|---|---|---|
| 出口带宽 | VPS 月费 + 流量费 | 多用户共享，但有上限 |
| IP 身份 | VPS 数量 × 地区数 | 完全共享，边际成本为零 |
| 连接质量 | 线路选择 + 中转投入 | 共享，但拥挤会降质 |

**核心商业逻辑**：你花固定成本买了一批"管道"，然后把管道的使用权按流量/时间切割卖给很多人。**用户越多，单位成本越低，利润越高** —— 这是一个典型的规模效应生意。

## 第二章：技术架构 —— 三层模型

商业机场的技术架构可以拆成三层，每层解决一个问题：

### 第一层：面板层（Panel）

**解决的问题：用户管理 + 商业运营**

- 用户注册 / 登录
- 套餐购买 + 支付
- 订阅链接生成
- 流量统计 + 到期管理
- 节点列表管理

**实现**：Xboard / SSPanel / AikoPanel  
**部署位置**：主控服务器

### 第二层：节点后端层（Node Backend）

**解决的问题：面板指令 → 代理服务的翻译器**

- 从面板 API 拉取：节点配置、用户列表、流量限额
- 动态生成 Xray 配置
- 统计每个用户的流量，上报给面板
- 用户到期 / 流量耗尽 → 自动断开

**实现**：XrayR / AikoR / Sing-box  
**部署位置**：每台节点服务器

### 第三层：代理内核层（Proxy Core）

**解决的问题：实际的流量加密和转发**

- 接收用户的加密连接
- 解密 → 获取目标地址
- 代替用户访问目标网站
- 将响应加密回传给用户

**实现**：Xray-core / sing-box  
**部署位置**：每台节点服务器（被节点后端管理）

### 三层之间的通信关系

```
面板 (Xboard)                    节点 (XrayR + Xray)
    │                                │
    │  ① 节点启动时拉取配置            │
    │ ◄──── GET /api/v1/server ──────│
    │                                │
    │  ② 定期拉取用户列表              │
    │ ◄──── GET /api/v1/user ────────│
    │                                │
    │  ③ 定期上报流量统计              │
    │ ────► POST /api/v1/traffic ───►│
    │                                │
    │  ④ 检查用户是否到期/超限          │
    │ ◄──── GET /api/v1/alive ───────│
```

**关键理解**：XrayR 不是独立的代理软件，它是一个**「翻译器 + 管理员」**。它把面板的商业逻辑（谁能用、能用多少流量）翻译成 Xray 的技术配置（inbound 规则），并且持续同步。

## 第三章：协议选择

代理协议决定了两件事：**安全性**（能不能被 GFW 识别和封锁）和 **性能**（速度和延迟）。

### 主流协议演进

```
早期                    中期                    当前（2025+）
SS → SSR → V2Ray/VMess → Trojan → VLESS+WS+TLS → VLESS+Reality
                                                   ↑ 推荐
```

### 协议对比

| 协议 | 抗封锁 | 速度 | 配置难度 | 适合场景 |
|---|---|---|---|---|
| **VLESS + Reality** | ★★★★★ | ★★★★★ | 中 | **首选**，不需要域名证书 |
| **VLESS + WS + TLS** | ★★★★ | ★★★ | 高 | 套 CDN 时用 |
| **Trojan** | ★★★★ | ★★★★ | 中 | 伪装 HTTPS |
| **Hysteria2** | ★★★ | ★★★★★ | 低 | UDP 加速，适合游戏 |
| **SS (2022)** | ★★★ | ★★★★ | 低 | 简单场景 |

### VLESS + Reality 为什么是当前最优解

传统 TLS 伪装的问题：你需要一个域名 + 证书，GFW 可以通过 SNI 指纹 + 证书指纹识别你在跑代理。

Reality 的做法：它不用你自己的证书，而是**"借用"**一个真实网站的 TLS 握手过程。GFW 看到的是一个完全正常的 HTTPS 连接到 `www.microsoft.com`，但实际数据在 TLS 层内被二次加密，只有你的客户端能解密。

```
用户 ──TLS握手(伪装连接microsoft.com)──► 你的VPS
      └──TLS层内部: 真实代理数据流──────►
GFW看到的：一个正常的HTTPS连接到微软
实际发生的：代理流量在TLS隧道内传输
```

## 第四章：用户生命周期

一个用户从听说你的机场到成为付费用户，经历这些步骤：

```
听说你的机场（推广/口碑）
    ↓
访问面板网站 → 注册账号
    ↓
浏览套餐 → 选择购买 → 付款
    ↓
获得订阅链接（一个URL）
    ↓
打开 Clash / V2rayN / Shadowrocket
    ↓
导入订阅链接 → 自动拉取所有节点
    ↓
选择节点 → 开始使用
    ↓
流量耗尽 / 到期 → 续费 or 流失
```

### 订阅链接是怎么工作的

这是整个系统最优雅的设计。订阅链接本质上是一个 **动态 API**：

```
https://panel.example.com/api/v1/client/subscribe?token=用户唯一token
```

客户端访问这个 URL 时，面板会：

1. 根据 token 识别用户身份
2. 查询该用户购买的套餐能访问哪些节点
3. 检查用户是否到期 / 流量是否耗尽
4. 动态生成当前可用的节点列表（包含协议、端口、密钥等）
5. 返回给客户端

**好处**：

- 你加了新节点，用户不需要做任何事，刷新订阅就能看到
- 你下线了某个节点，用户刷新后自动消失
- 用户到期了，返回空列表，自动无法使用
- 每个用户的 token 不同，可以追踪和限制

## 第五章：流量计费的底层逻辑

### 流量怎么统计

```
用户 ──代理流量──► Xray (节点)
                    │
                    │ Xray 记录每个用户的上传/下载字节数
                    │ （通过 inbound 里的 user email 字段区分用户）
                    ↓
                  XrayR 定期读取 Xray 的流量统计 API
                    │
                    │ 每隔 60 秒上报一次给面板
                    ↓
                  Xboard 面板累加到用户账户
                    │
                    │ 剩余流量 = 套餐总流量 - 已用流量
                    ↓
                  流量耗尽 → 面板标记用户为禁用
                    │
                    │ 下一次 XrayR 拉取用户列表时
                    ↓
                  XrayR 将该用户从 Xray 配置中移除 → 断开连接
```

### 流量倍率

这是机场的一个重要运营概念。不同节点可以设置不同的流量倍率：

- **1x 倍率**：用 1GB 算 1GB（普通节点）
- **0.5x 倍率**：用 1GB 只算 0.5GB（促销 / 引流节点）
- **2x 倍率**：用 1GB 算 2GB（高成本线路，如 IPLC 专线）

倍率让你可以对不同成本的线路差异化定价，而不需要给每条线路单独做套餐。

## 第六章：支付系统

### 支付链路

```
用户点击购买
    ↓
面板生成订单 → 调用支付接口
    ↓
┌──────────────────────────────────────┐
│ 支付网关                              │
│                                      │
│ 方案A：易支付（支付宝/微信）            │
│   - 对接第三方易支付平台               │
│   - 费率 1-3%                        │
│   - 有跑路风险                        │
│                                      │
│ 方案B：USDT (加密货币)                │
│   - 对接 USDT TRC20 收款              │
│   - 无第三方风险                      │
│   - 用户门槛高                        │
│                                      │
│ 方案C：手动确认                       │
│   - 用户转账后提交截图                 │
│   - 你手动确认开通                     │
│   - 零成本但不可规模化                 │
│                                      │
│ 方案D：Stripe / PayPal               │
│   - 国际支付                          │
│   - 需要海外企业主体                   │
│   - 适合面向海外用户                   │
│                                      │
└──────────────────────────────────────┘
    ↓
支付成功 → 回调通知面板
    ↓
面板自动开通套餐 → 用户立即可用
```

### 初期建议

**先用手动确认**，不花任何成本验证商业模式。有了稳定用户后再接易支付。

## 第七章：线路架构 —— 直连 vs 中转

这是决定用户体验和你成本结构的核心选择。

### 直连架构

```
用户(中国) ──── GFW ──── 你的美国VPS ──── 目标网站
              ↑
          直接穿越防火墙
```

**优点**：成本低，架构简单  
**缺点**：

- 高峰期国际出口拥堵，速度不稳定
- IP 容易被墙（直接暴露给 GFW）
- 被墙后需要换 IP / 换端口

### 中转架构（商业机场标配）

```
用户(中国) ── 国内中转服务器 ── 专线/优化线路 ── 海外节点 ── 目标网站
                ↑                    ↑
            不过GFW               绕过拥堵的国际出口
```

**中转的本质**：用一台国内服务器做流量中继，让用户的流量走优化过的路径出海，而不是走默认的拥挤国际出口。

#### 中转方案对比

| 方案 | 延迟 | 带宽 | 成本 | 稳定性 |
|---|---|---|---|---|
| **BGP 中转** | 50-100ms | 中 | ¥50-200/月 | 中 |
| **CN2 GIA** | 40-80ms | 中 | VPS 自带 | 高 |
| **IPLC 专线** | 30-60ms | 高 | ¥10-30/Mbps/月 | 极高 |
| **IEPL 专线** | 30-60ms | 高 | ¥15-40/Mbps/月 | 极高 |
| **Cloudflare CDN** | 不稳定 | 低 | 免费 | 低 |

#### 初期建议

**先不做中转，直连验证**。当用户反馈"速度不行"时，再考虑加中转。中转会让你的成本至少翻倍。

## 第八章：运营流程

### 日常运维

```
每日检查：
├── 节点是否在线（面板后台一眼可见）
├── 用户投诉/反馈（Telegram 群 / 工单）
└── 收入/支出对账

定期维护：
├── 更新 Xray 内核（跟进抗封锁策略）
├── 更新面板版本
├── 检查 VPS 续费情况
└── 清理过期用户数据

应急响应：
├── IP 被墙 → 换 IP / 切换端口 / 启用备用节点
├── 节点宕机 → 重启服务 / 换机器
└── 大规模封锁 → 切换协议 / 启用中转
```

### 用户获取渠道

| 渠道 | 成本 | 转化率 | 适合阶段 |
|---|---|---|---|
| **Telegram 群** | 免费 | 中 | 初期 |
| **口碑推荐（邀请返利）** | 低 | 高 | 所有阶段 |
| **机场评测站投稿** | ¥200-500 | 中 | 中期 |
| **社交媒体** | 免费 | 低 | 长期品牌 |

## 第九章：成本与利润模型

### 成本结构（以 8 节点方案为例）

```
固定成本（每月）：
├── VPS x8 台：¥200-400/月（取决于选廉价还是优质）
├── 域名：¥60/年 ≈ ¥5/月
├── 面板服务器（与节点共用）：¥0
├── 中转（如果加）：¥200-500/月
└── 总计：¥200-900/月

可变成本：
├── 支付手续费：1-3%
├── 超额流量费：通常 VPS 含 1-2TB/月
└── 客服时间成本：你自己的时间
```

### 收入模型

```
假设定价：
├── 入门套餐：¥20/月（100GB）
├── 标准套餐：¥35/月（300GB）
└── 高级套餐：¥60/月（不限量）

假设用户分布（100个用户）：
├── 60人入门：¥1200/月
├── 30人标准：¥1050/月
└── 10人高级：¥600/月
└── 总收入：¥2850/月

利润：
├── 成本 ¥400（不含中转）
├── 收入 ¥2850
└── 净利润 ¥2450/月（毛利率 86%）
```

### 规模效应

```
用户数:    10人     50人      100人      500人
收入:     ¥300    ¥1400     ¥2850     ¥14000
成本:     ¥250    ¥400      ¥600      ¥2000
利润:     ¥50     ¥1000     ¥2250     ¥12000
利润率:    17%     71%       79%        86%
```

**关键洞察**：前 20 个用户几乎不赚钱，但越过盈亏平衡点后，每增加一个用户几乎是纯利润。

## 第十章：风险清单

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| **IP 被墙** | 高 | 节点不可用 | 备用节点、快速换 IP |
| **VPS 商封号** | 中 | 数据丢失 | 定期备份、不在同一商家 all-in |
| **用户投诉/退款** | 中 | 信誉损失 | 明确 TOS、合理退款政策 |
| **GFW 升级封锁** | 低-中 | 全线不可用 | 跟进最新协议、多协议备选 |
| **同行恶意攻击 (DDoS)** | 低 | 节点瘫痪 | 选有 DDoS 防护的 VPS |
| **支付渠道被切** | 中 | 无法收款 | 多支付渠道、加密货币备选 |

## 第十一章：3X-UI vs Xboard

3X-UI 的定位是**个人代理管理面板**，不是商业运营工具。区别：

| 能力 | 3X-UI | Xboard |
|---|---|---|
| 用户注册/登录 | ❌ 手动创建 | ✅ 自助注册 |
| 套餐/计费 | ❌ 手动管理 | ✅ 自动化 |
| 支付系统 | ❌ 无 | ✅ 对接支付宝/USDT |
| 订阅链接 | ⚠️ 基础 | ✅ 完整（含流量限制） |
| 流量统计 | ⚠️ 节点级 | ✅ 用户级 |
| 多节点管理 | ❌ 每台单独管 | ✅ 中心化管理 |
| 公告/工单 | ❌ 无 | ✅ 有 |
| 邀请返利 | ❌ 无 | ✅ 有 |

**升级路径**：3X-UI 继续保留做个人用的代理，Xboard 做商业面板。两者可以共存。

## 总结：这门生意的本质

```
                    你的核心资产
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   服务器资源          技术能力          用户信任
   (VPS+带宽)      (部署+运维)        (稳定+速度)
        │                │                │
        └────────────────┼────────────────┘
                         │
                    规模化复制
                         │
              固定成本 ÷ 用户数 → 趋近于零
                         │
                    利润 = 规模
```

**一句话**：机场是一个前期投入固定、边际成本极低的规模效应生意。技术门槛不高，竞争壁垒在于**运营效率**和**用户信任**。
