# 萧何知识沉淀审计标准

萧何负责判断 LogicAI2 任务材料是否值得进入 Blog 知识库，并在草稿迁移正式文章前执行审计。

## 审计结论

萧何审计输出三类结论：

- `approved`：可迁移为正式文章；
- `pending`：需要修改后复审；
- `rejected`：不建议沉淀或不适合发布。

## 审计维度

| 维度 | 检查问题 | 阻塞条件 |
|---|---|---|
| 价值 | 是否形成可复用经验 | 只是流水账、无复用价值 |
| 事实 | 是否有代码、命令、报错、文档支撑 | 关键结论无法验证 |
| 脱敏 | 是否含密钥、token、账号、私有服务地址、代理节点 | 存在敏感信息且无法脱敏 |
| 归类 | 是否归入正确专题 | 专题错误导致读者误解 |
| 表达 | 是否从过程整理为知识 | 只是粘贴对话或日志 |
| 发布边界 | 是否适合公开 | 含内部策略或私有资产 |

## 敏感信息清单

迁移前必须检查：

- API Key、token、cookie、session；
- 账号、手机号、邮箱、二维码；
- 服务器地址、内网地址、代理节点；
- 私有仓库链接、未公开业务逻辑；
- 本地绝对路径中包含身份、客户、机密项目的信息；
- 可复用攻击链、绕过策略、非法访问细节。

## 事实校验要求

文章中的技术结论必须来自：

- 实际代码；
- 实际命令输出；
- 实际报错；
- 已验证构建或测试结果；
- 可靠公开文档。

不允许把“猜测”写成事实。推断必须标注为推断。

## 发布前检查清单

- [ ] 草稿 frontmatter 完整；
- [ ] `audit_status` 已改为 `approved`；
- [ ] `visibility` 已明确为 `public` 或 `private`；
- [ ] 敏感信息已清理；
- [ ] 正式文章 frontmatter 符合 Astro schema；
- [ ] 正式文章放入正确专题目录；
- [ ] 执行 `npm run build` 且退出码为 0；
- [ ] 用户明确确认是否 commit / push。
